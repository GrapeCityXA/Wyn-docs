# 部署与运维

## 部署形态

| 形态 | 适用规模 | 特点 |
| --- | --- | --- |
| 单机部署 | 部门级、试点、开发测试 | 安装简单，一个服务进程 + 一个数据库 |
| 应用与数据分离 | 中型企业 | Web 服务与业务库分开，便于独立扩容与备份 |
| 集群部署 | 大型企业、高并发、嵌入式场景 | 多节点负载均衡，无单点故障 |

嵌入式集成场景（Wyn 作为自有产品的一部分）通常需要集群，因为可用性要求继承自宿主产品，不能比宿主产品先挂。

## 环境要求要点

具体版本与参数要求随版本变化,以官方文档为准。规划时先确认这四项：

**操作系统。** Windows Server 与主流 Linux 发行版均支持，容器化部署支持 Docker。

**数据库。** 需要独立的业务库存储系统配置、用户、权限与元数据，支持主流关系型数据库。**不要与分析用的业务数据源混用同一个库实例**——分析查询的负载特征与业务库不同，混用会互相影响。

**内存与磁盘。** 取决于并发用户数与数据量。嵌入式场景下并发用户数往往被低估（宿主产品的全部用户都是潜在访问者），建议按峰值用户数预留。

**网络。** 若对接内网数据库，需确认 Wyn 服务器到各数据源之间的网络可达性。这是实施阶段最常见的阻塞点。

## 升级

升级前必做两件事：**备份业务库**、**在测试环境完整走一遍升级流程**。生产环境直接升级的风险不在于升级本身，而在于自定义内容（自定义组件、定制样式、集成代码）在新版本下的兼容性。

升级顺序：备份 → 测试环境升级验证 → 生产环境停服升级 → 回归验证核心仪表板与集成链路。

## 备份

需要备份的是**业务库**（系统配置、用户权限、元数据、数据集定义）和**文件存储**（上传的图片、Excel、导出文件）。仪表板与数据集定义都在数据库里，不备份数据库等于丢失全部设计成果。

建议策略：业务库每日全量 + 文件存储增量，保留最近 30 天。备份文件异机存放。

## 监控

生产环境至少监控四项：服务进程存活、数据库连接、内存使用率、慢查询。分析类应用的性能问题通常先在慢查询上体现，而不是在服务进程上。
