# 行业解决方案

行业方案按行业独立成目录，每个目录结构一致，便于横向对比与复用。

## 已有行业

| 行业 | 核心场景 | 文档 |
| --- | --- | --- |
| 制造业 | 生产运营、质量、供应链、仓储、经营分析 | [制造业方案](manufacturing/README.md) |
| 计量检测 | 实验室运营驾驶舱、检测周期、设备效能、质量趋势 | [计量检测方案](lims-metrology/README.md) |

## 目录结构约定

每个行业目录保持同样的结构，新进行业直接复制即可：

```
02-solutions/<industry-slug>/
├─ README.md          # 主文档：痛点 → 方案 → 场景 → 交付
├─ images/            # 本行业专用图，从 PPT 逐页导出
└─ case-*.md          # 可选：单独的客户案例
```

跨行业复用的架构图、通用示意图放 [`_shared/images/`](_shared/images/)，引用时用相对路径 `../_shared/images/xxx.png`。判断标准：**只在两个以上行业出现、且内容完全一致的图，才移到 `_shared`**。过早共用会让单篇文档失去自包含性。

## 主文档的固定结构

行业方案文档统一按这个顺序写，客户在任何一个行业页面都能预期到哪里找什么：

1. **一句话结论** —— 这个方案解决什么问题，首段就要说清
2. **行业痛点** —— 三到四个，每个带一句具体现象，不要抽象名词
3. **方案结构** —— 配一张架构图
4. **典型应用场景** —— 表格形式，场景 / 指标 / 价值三列
5. **与既有系统的关系** —— 客户最关心：要不要替换、要不要改造
6. **交付形态** —— 嵌入、独立门户、大屏
7. **相关文档** —— 链接到产品能力层

## 原始 PPT 的处理

行业方案 PPT 体积大（单个 40–50MB），不提交到仓库：

1. 把 PPT 逐页导出为 PNG，按 `章节号-主题.png` 命名，放进本行业 `images/`
2. 有文字价值的页面提炼成 `README.md` 的正文，不要只放图
3. 原始 PPT 打包挂到 GitHub Releases，README 里给出[下载说明](../../downloads/README.md)链接

只放图不放文字，是这类文档最常见的失误——图里的字搜不到，AI 也读不到，客户和搜索引擎都找不到你。
