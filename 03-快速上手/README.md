# 快速上手

## 五分钟跑通一个仪表板

1. **安装或访问环境** —— 使用试用环境，或按[部署文档](../04-部署运维/README.md)在自有服务器安装
2. **连接数据源** —— 添加数据库连接，或直接上传一份 Excel
3. **创建数据集** —— 选择表，拖入需要的字段，必要时加计算字段
4. **新建仪表板** —— 拖入图表组件，绑定字段，选择图表类型
5. **预览与分享** —— 调整布局后发布，设置访问权限

每一步的详细操作见下方对应章节。

## 为什么帮助文档不转 Markdown

原先考虑把 4 个帮助文档 PDF（合计约 580MB）全部转成 Markdown 放进仓库。评估后不采用：

**一、体积不可行。** 单个 PDF 均超过 100MB，超出 GitHub 单文件上限，普通方式无法推送。全文转换会产生数千张截图，仓库体积膨胀到无法克隆的程度。

**二、版本必然失真。** 帮助文档跟随产品版本迭代。转出的 Markdown 是静态快照，产品更新后很快与实现不一致，客户照着操作反而出错。**过时的文档比没有文档危害更大。**

**三、在线文档已经可检索。** 官方帮助文档带搜索，且始终是最新版本。仓库这一层的作用是**导航**——让客户知道该去哪一章找，而不是复制一份会过期的副本。

所以本仓库只维护上面这张「主题 → 官方章节」映射表。这张表本身有价值（客户往往不知道自己的问题属于哪个模块），维护成本又极低。
