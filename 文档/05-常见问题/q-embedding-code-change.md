# 嵌入式集成需要改我的产品代码吗？

**需要改，但改动量小，集中在接入层的脚手架代码，不触及你的业务逻辑。** 典型工作量是前端加一个页面容器与初始化调用、后端加一个令牌签发接口，通常以人天计而不是人月。

## 具体改在哪

**前端。** 在需要展示分析的页面引入嵌入资源，把容器节点交给嵌入接口，传入仪表板标识与参数。这一步是新增代码，不修改既有页面逻辑。

**后端。** 增加一个令牌签发接口：用自有系统的账号信息换取 Wyn 的访问令牌。这个接口需要处理的是映射关系——你的用户 ID 对应 Wyn 的哪个用户、角色如何对应、数据权限参数怎么传。

**配置。** 跨域、Cookie 域、回调地址这类配置项，和接入任何第三方组件的工作量类似。

## 不需要改的地方

- 不需要改动既有业务表结构
- 不需要在自有系统里重建权限模型，映射即可
- 不需要把用户数据同步到 Wyn 的独立账号体系（除非选择账号同步方案）

## 容易低估的部分

真正花时间的往往不是「嵌进去」，而是**权限与数据范围的映射**。分析场景里，同一个仪表板给不同客户、不同区域的人看，必须显示各自的数据。这块要设计清楚：参数由谁注入、能否被前端篡改、行级权限在哪一层生效。

建议在方案阶段就把这部分画出来，而不是留到联调时试。
