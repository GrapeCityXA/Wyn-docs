# 嵌入式集成

这一页面向开发者与架构师。核心问题只有一个：**怎么让 Wyn 的分析能力变成你产品的一部分，而不是一个需要用户额外登录的外部系统。**

## 三种嵌入方式

| 方式 | 适用场景 | 用户感知 |
| --- | --- | --- |
| URL / iframe 嵌入 | 快速集成，独立页面展示 | 在新窗口或内嵌区域看到分析页 |
| API 嵌入（推荐） | 深度集成，界面融合 | 分析与自有界面无缝衔接 |
| 组件级嵌入 | 只要单个图表或指标卡 | 分析元素成为页面的一部分 |

选择依据不是技术先进程度，而是**用户体验要求的融合度**。如果只是想给用户一个「打开报表」的入口，iframe 就够；如果要让用户感觉分析功能是自己产品原生的，必须走 API 嵌入。

## 集成的四个技术要点

**单点登录。** 用户在自有系统已登录，进入分析页面不应二次认证。Wyn 支持基于令牌的单点登录，由自有系统签发身份令牌，Wyn 校验后建立会话。

**身份与权限传递。** 用户在自有系统里的角色、所属组织、可见数据范围，要能映射到 Wyn 的权限体系。这块是集成项目里最容易出问题的地方——设计时就要明确：权限由谁定义、在哪个系统维护、冲突时以谁为准。

**数据权限过滤。** 同一张仪表板，不同客户、不同区域的人看到的应该是各自的数据。通常通过参数传递 + 行级权限实现，参数值由宿主系统注入，不能由前端自由传入。

**主题与外观。** 分析页面的配色、字体、间距与自有产品一致，用户不会意识到这是嵌入的第三方模块。

## 能力边界

嵌入能力有明确范围，提前了解可以避免实施阶段的预期错位：

**支持：**

- 嵌入仪表板、报表、大屏，支持传入参数与筛选条件
- 通过 API 控制页面行为（切换、刷新、导出、全屏）
- 扩展自定义可视化组件

**不支持：**

- 把设计器完整嵌入给最终用户做自助建模（需要单独的权限与授权模型）

具体的接口清单、鉴权流程与代码示例见[官方帮助文档](https://www.grapecity.com.cn/solutions/wyn/help/docs/embedded-integration)。
