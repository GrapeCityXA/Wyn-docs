# AI 问数与对话式分析

Wyn 把自然语言问答接进 BI：用户说「上个月各区域的销售额排名」，系统直接返回图表与结论，不需要先建数据集、拖字段、调配色。这项能力的价值不在于炫技，而在于把「提需求 → 排队 → 等交付」变成「自己拿到答案」。

> 完整能力介绍见《Wyn BI 全景 AI 能力解析》，原文件见仓库 Releases 页。

## 三类受益者

**管理决策：告别等待。** 管理层的问题往往有时效性——某个指标为什么波动、某区域为什么掉了。等 IT 排期拿到报表时，决策窗口已经过去。AI 问数让这类问题当场得到回应。

**业务运营：全员可用。** 业务人员懂业务不懂建模，过去要么提需求要么自己学工具。自然语言是最低门槛的入口，让数据分析从事项变成习惯。

**项目交付：加速实施。** 实施方与 IT 在项目里通过对话快速生成图表与仪表板，把时间花在业务理解上而不是画图操作上。

## AI 能力如何落在 BI 里

AI 不是独立于产品外的一个对话框，而是嵌入在分析全流程中。按数据流转的顺序看，各环节的增强点分别是：

| 环节 | AI 的作用 |
| --- | --- |
| 数据接入 | 辅助识别字段语义，自动建议数据类型与关联关系 |
| 建模 | 依据自然语言描述生成计算字段与指标定义 |
| 可视化 | 用一句话生成初版图表，再手工调整样式 |
| 交互 | 对话式追问，替代层层点击的筛选与钻取 |
| 分发 | 自动生成图表与页面的文字解读 |

这个分布决定了 AI 在 Wyn 里是「一个能用的功能」还是「一个演示品」——它嵌在流程里，而不是旁边挂一个聊天框。

## 落地前提

AI 问数的效果高度依赖数据底座质量，这一点需要在客户沟通时提前说清，否则容易变成「演示很好，上线不行」：

- **指标口径要预先定义。** 大模型需要知道「销售额」到底指含税还是不含税、是否扣退货。语义层没做好，问出来的答案就是错的。
- **表与字段的业务名称要维护。** 数据库里的 `amt_tax_incl` 模型不认识，但「含税金额」它认识。
- **权限体系必须前置。** 用户不能通过自然语言绕过行级权限，这是安全底线。

这三件事做好，AI 问数才稳定；做不好，问题会被归因成「AI 不准」。
