# 原始文件下载

本仓库只存 Markdown 正文与配图。白皮书、行业方案 PPT、产品介绍等原始文件体积较大，统一挂在仓库的 Releases 页面，按产品版本组织。

## 为什么不放仓库里

**一、GitHub 单文件上限 100MB。** 帮助文档 PDF 单个 107–171MB，用普通方式提交会被拒绝。

**二、仓库体积会失控。** 原始文件一旦进入 Git 历史，即使后来删除，历史里仍然留着，克隆体积永远降不下来。放进 Releases 的附件不进入 Git 历史。

**三、版本对应更清晰。** Releases 天然按版本归档，客户下载时能明确知道拿的是哪个产品版本的资料。

## 如何发布一个 Release

1. 在仓库页面右下角点 **Releases → Draft a new release**
2. **Tag** 用产品版本号，例如 `v9.0u1`（与官方版本号一致，不要自创编号）
3. **Title** 写清楚，例如 `Wyn V9.0 Update1 产品资料`
4. 把原始文件拖到附件区，单个附件上限 2GB
5. 说明里列出本次变更：新增哪些文档、更新了哪些
6. 发布

> 帮助文档的 4 册 PDF 合计约 580MB，若确需提供下载，建议先压成 zip 再上传，可降到 400MB 左右。

## 注意

`*.pdf`、`*.pptx`、`*.docx`、`*.zip` 已在 [.gitignore](../.gitignore) 中排除。如果需要某份小文件进仓库，用 `git add -f <文件>` 强制添加，但先确认它真的需要跟随代码一起版本化。
